## 一、创意与玩法

我一直觉得「一笔画」这个玩法被低估了。它天生有一个叙事：**你亲手画下一条路，然后看着什么东西沿着它走**。大多数一笔画游戏只把它当解谜，画完就结算，那条线本身没有性格。

所以《墨童》想做的是：**让那条线有性格，并且让它的性格反噬你**。

玩法一句话：在宣纸上按住拖动，画一笔穿过所有朱砂，收笔落在「墨」印上；笔尖碰不得墨渍，每关墨量有限。第 4 关起，会出现一个**墨影**——它先走一步，用的是从你前几关笔画里学来的走法。你爱绕远，它就绕；你爱贴着墨渍走，它就贴着边；你爱先拿最近的朱砂，它就按最近优先去抢。它抢走的朱砂，你这一关就拿不到了。

七关之后收卷：这一局你画下的每一笔，都在一页册页上，可以存下来。

**为什么选这个方向**：官方灵感库里有一栏是「故事与 AI NPC——让角色有记忆，让选择改变故事」。《墨童》里的「记忆」不是聊天记录，而是**你的手感**：它记住的不是你说过什么，而是你怎么走路。这个记忆是可见的、可验证的、不需要云端。

## 二、创作过程

**第一天（11-13）**：把「选赛 → 定题 → 立规格 → 写核心 → 上真环境 → 举证 → 盲排 → 包装」这条流水线跑完。

1. **开工前先问「我们对要做的东西达成一致了吗」**：写了 `docs/00-BRIEF.md`（把官方海报上的日程、奖项、两条提交要求逐条摘下来）、`docs/01-SPEC.md`（先写演示脚本，再写 13 条能跑命令判定的验收条件）、`docs/07-UI.md`（风格预设、六张外部尺子、一个记忆点、主屏规格）。
2. **先把骨架放上真环境**：`npm run build` 之后立刻部署到 GitHub Pages，之后每一步都对着真地址验。
3. **核心逻辑与渲染分家**：`src/core/` 里没有一行 DOM 代码——几何、关卡生成、笔画判定、学习模型都能在 Node 里跑单元测试；`src/render/` 只负责画。
4. **每完成一条验收条件推一次分支**，断了不丢。

**关于素材**：这个作品没有任何图片和音频文件。宣纸的纤维、远山、墨的洇、朱砂的颗粒、印章的侵蚀孔洞，全部是 `src/render/paper.ts` 与 `src/render/ink.ts` 里现画的；音效是 WebAudio 合成的（拨弦用三角波 + 指数衰减，笔触声用带通滤波的白噪声，音量跟着笔速走）。

## 三、工具应用与体验

- **主控与实现**：CodeBuddy（CodeBuddy CLI / WorkBuddy）。整场是「我先定规格、再自己施工、最后自己举证」，Multica 那边只记账与留痕。
- **TypeScript（strict）+ Vite**：类型是这一场的安全网——学习模型有五个参数、关卡有七套配置，靠类型和 23 条单元测试才敢在一天里改十几轮。
- **Playwright（无头 Chromium）**：不做「人眼看一眼就算过」。`scripts/e2e.mjs` 真的把生产构建点开、点「落笔」、让游戏自己走完七关、点「收卷」、检查册页生成、切到 414px 检查溢出、收集 console 错误。视频也是用它录的（`scripts/record.mjs`），所以视频里跑的就是线上那一份产物。
- **ffmpeg + Pillow 做字幕**：中文字幕不用 ffmpeg 的 drawtext（字体与编码在 Windows 上很容易翻车），改成 Pillow 先把字幕渲成透明 PNG，再用 ffmpeg 按时间窗叠加。

**体验上的感受**：AI 编程在这一场的价值不在「写得多」，而在「敢改」。视觉我改了四轮（笔触从一条黑带子改成五层叠加、墨渍从黑色石头改成一团洇开的墨、标题页从网页弹窗改成题跋式版式、册页从竖版改成横版四列），每一轮都是「改完 → 截图 → 看图 → 再改」。如果每次改都要手工验一遍七关，这四轮改不完。

## 四、问题解决

挑四个真问题，都是「不看图发现不了」的：

1. **笔触中间有一条白缝**。第一版用「左边缘正向 + 右边缘反向」拼一个多边形填色，在曲率大的地方自交，非零环绕规则把中间挖空了。隔离测试（把笔触单独画在一张 900×400 的画布上，再用像素采样看截面亮度）之后改成：先平滑中心线、把宽度抖动从 ±8% 降到 ±3.5%，再用三层不同宽度叠加 + 边缘聚墨描边 + 颗粒，问题消失，顺便更像毛笔。
2. **墨渍像黑色石头**。原因是多瓣径向渐变 + 硬边缘，看起来是 3D 球。改成：多瓣融合 + 整张精灵做 1.6px 高斯模糊 + 降低不透明度，才读作「洇进纸里」。
3. **墨影的路线是折线**。贪近这一项会把访问顺序改成「最近优先」，我一开始直接把这些点连成折线，画面上像铅笔乱划。改成过这些点做 Catmull-Rom 样条。
4. **关卡像乱涂**。第一版每个控制点各自随机偏移，生成的基准路线来回穿插、自己跟自己交叉，玩家根本看不出「该往哪走」。改成整条路线只允许 1–2 个平滑起伏（同相位正弦 + 两端收窄），并给了个「墨渍不许压路线、路线必须在墨量内可走」的自动检查——七关全部由测试守门。

## 五、总结

- **AI 用法要做成「可验证的记忆」，不要停留在概念**：墨影学的五个参数，每一个都能从笔画里算出来、都有单测、同一习性下路线完全可复现。评审如果要挑，可以照着 `docs/04-PROOF.md` 一条条重跑。
- **给它设一条「不许把玩家玩死」的边界**：墨影最多抢 40% 的朱砂，写死在 `planShadow` 里。AI 让游戏更有性格，但不能让游戏不可通关。
- **一天做完的关键不是写得快，是闸门清楚**：规格先行、真环境先行、每条验收条件配一条命令。改四轮视觉还能按时交，靠的是每次改完都能一条命令验回来。

**接下来想做的**：让墨影在「同一关里」边看你画边学（现在是关卡之间学），以及把习性做成可以传给他人的「墨谱」——你的一局画完，别人可以下载你的墨影来对自己的局。
